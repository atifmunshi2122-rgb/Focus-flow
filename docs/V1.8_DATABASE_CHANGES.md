# FocusFlow & Finance v1.8.0 — Database Schema & Persistence Changes

## Overview
FocusFlow & Finance v1.8.0 introduces support for new persistent domain entities supporting the 15 Zero-AI features while strictly adhering to tenant isolation rules and dual-persistence support (local JSON store for development/offline fallback and Cloud Firestore for authoritative cloud persistence).

---

## 1. Local Database Schema Additions (`server/db.ts`)

The `DatabaseSchema` interface in `server/db.ts` was extended with 8 new typed collections:

```typescript
export interface DatabaseSchema {
  // Existing v1.7.0 collections...
  users: User[];
  userSettings: UserSettings[];
  tasks: Task[];
  // ...
  
  // New v1.8.0 Collections:
  skillNodes?: SkillNode[];
  whiteboardDrawings?: WhiteboardDrawing[];
  examSimulations?: ExamSimulationState[];
  decisionEntries?: DecisionEntry[];
  doomscrollLogs?: DoomscrollTaxEntry[];
  lifeMilestones?: LifeMilestone[];
  timeCapsules?: TimeCapsuleLetter[];
  emergencyAssetProfiles?: EmergencyAssetProfile[];
}
```

### Schema Initialization
In `DatabaseService.ensureBaseDefaults()`, all new arrays are guaranteed to initialize as empty arrays if absent in existing JSON files:

```typescript
this.db.skillNodes = this.db.skillNodes || [];
this.db.whiteboardDrawings = this.db.whiteboardDrawings || [];
this.db.examSimulations = this.db.examSimulations || [];
this.db.decisionEntries = this.db.decisionEntries || [];
this.db.doomscrollLogs = this.db.doomscrollLogs || [];
this.db.lifeMilestones = this.db.lifeMilestones || [];
this.db.timeCapsules = this.db.timeCapsules || [];
this.db.emergencyAssetProfiles = this.db.emergencyAssetProfiles || [];
```

## 2. New DatabaseService Methods

| Method Signature | Return Type | Description | Tenant Isolated |
|------------------|-------------|-------------|:---------------:|
| `getSkillNodes(userId)` | `SkillNode[]` | Returns skill nodes for the tenant or global presets | Yes |
| `saveSkillNode(node)` | `SkillNode` | Upserts a skill tree node | Yes |
| `getWhiteboardDrawings(userId)` | `WhiteboardDrawing[]` | Retrieves user's saved whiteboard sketches | Yes |
| `saveWhiteboardDrawing(drawing)` | `WhiteboardDrawing` | Upserts a whiteboard drawing record | Yes |
| `deleteWhiteboardDrawing(id, userId)` | `boolean` | Safely removes a drawing owned by the user | Yes |
| `getExamSimulations(userId)` | `ExamSimulationState[]` | Returns user's saved exam setups | Yes |
| `saveExamSimulation(sim)` | `ExamSimulationState` | Upserts exam simulation state | Yes |
| `getDecisionEntries(userId)` | `DecisionEntry[]` | Retrieves decision journal entries | Yes |
| `saveDecisionEntry(entry)` | `DecisionEntry` | Upserts a decision journal record | Yes |
| `getDoomscrollLogs(userId)` | `DoomscrollTaxEntry[]` | Retrieves user's distraction tax logs | Yes |
| `saveDoomscrollLog(entry)` | `DoomscrollTaxEntry` | Adds a new self-tax event to the ledger | Yes |
| `clearDoomscrollLogs(userId)` | `boolean` | Resets the user's doomscroll tax jar | Yes |
| `getTimeCapsules(userId)` | `TimeCapsuleLetter[]` | Retrieves all sealed and unsealed time capsules | Yes |
| `saveTimeCapsule(letter)` | `TimeCapsuleLetter` | Creates or updates a time capsule | Yes |
| `deleteTimeCapsule(id, userId)` | `boolean` | Deletes a time capsule owned by the tenant | Yes |
| `getEmergencyProfile(userId)` | `EmergencyAssetProfile \| null` | Fetches emergency contacts and asset masks | Yes |
| `saveEmergencyProfile(profile)` | `EmergencyAssetProfile` | Upserts the emergency profile record | Yes |

## 3. UserSettings Schema Extensions (`src/types/index.ts`)

The `UserSettings` schema was updated to support persistent user preferences for v1.8 features:

```typescript
export interface UserSettings {
  // Existing settings...
  hourlyEarningRate?: number;          // Feature 1: Time-vs-Money rate
  timeVsMoneyEnabled?: boolean;        // Feature 1: Toggle badge display
  doomscrollHourlyTax?: number;        // Feature 10: Tax rate per hour
  birthDate?: string;                  // Feature 11: YYYY-MM-DD for Life in Weeks
  lifeHorizonYears?: number;           // Feature 11: Default 90 years
  binauralBeatsVolume?: number;        // Feature 5: Default audio volume (0-1)
  binauralBeatsPreset?: string;        // Feature 5: Default wave preset ID
  typingWarmupEnabled?: boolean;       // Feature 12: Auto-prompt before pomodoro
  hideFinancialInReceipt?: boolean;    // Feature 6: Privacy masking in receipt
}
```

## 4. Cloud Firestore Collection Layout

In production Cloud Firestore, the new collections are mapped directly under the user's document path to ensure hardware-enforced tenant isolation:

- `users/{userId}/skill_nodes/{nodeId}`
- `users/{userId}/whiteboards/{drawingId}`
- `users/{userId}/exam_simulations/{simulationId}`
- `users/{userId}/decisions/{decisionId}`
- `users/{userId}/doomscroll_logs/{logId}`
- `users/{userId}/time_capsules/{capsuleId}`
- `users/{userId}/emergency_profile/default`
